# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Docs: MCP servers guide (`docs/mcp.md`): source schema, variable references, per-tool translation, and limits (#1).
- OpenCode: map `startup_timeout_sec` to per-server `timeout.startup` (milliseconds) in the v2 layout while preserving sibling `catalog` and `execution` timeout keys (#3).
- ADR 0021 recording MCP source validation rules, literal-secret import behavior, and adapter alignment (#3).

### Changed
- Source loader and adapters share one HTTP header scheme rule (`^[A-Za-z][A-Za-z0-9._-]*$`) (#3).
- Preserve `description` on `ServerEntry` through `mcp.jsonc` load/render round trips without writing it to any tool (#3).
- Update Claude Code `CLAUDE_CONFIG_DIR` notes: relocation of `.claude.json` is verified on Windows; relocation of `CLAUDE.md` and skills, and Linux/macOS, are unverified (#3).

### Fixed
- OpenCode: always own `headers` so removing the last header of an owned server removes `headers` from `opencode.jsonc` (#3).
- All adapters: report a `Conflict` (without exposing secret values) when an unowned server carries literal HTTP headers not in `mcp.jsonc`, while keeping owned-server header preservation in Codex and Antigravity (#3).
- `scripts/hooks/pre-commit`: probe `python3`, `python`, and `py -3` by executing a Python 3 check instead of stopping on Windows Store stubs or a Python 2 (#3).
- OpenCode: a new value for a key that holds its default (`"headers": {}`, `"disabled": false`) replaces it instead of adding the key a second time (#3).
- OpenCode: a timeout change edits only `timeout.startup`, keeping comments and other keys in that object, and corrects a non-integer `startup` (#3).
- OpenCode: a `startup_timeout_sec` too large for milliseconds is reported as `Unsupported` instead of crashing; an integer too large for a float is a source error (#3).
- OpenCode: when a key written twice in the user's file would defeat an edit, the edit fails and the file is left unchanged instead of the change being reported as applied; later runs report the same failure until the duplicate key is removed (#3).
- `init`: an OpenCode v1 entry is adopted when only the timeout (which v1 cannot store) differs; `ToolAdapter.normalize_mcp` takes an optional `env` for this (#3).
- Antigravity: a `<scheme> ${VAR}` header is treated alike by `init` and `sync` (not literal), and in all four adapters a literal header on an unowned server is a `Conflict` even when the source server is disabled or cannot be written (#3).
- `init`: a startup timeout that a tool's file holds out of range (not positive, above what OpenCode accepts, or above a 64-bit TOML integer in Codex) is not imported, so it no longer makes the whole proposed source invalid; a non-string header value counts as literal for `init` and `sync` alike (#3).
- Header values: a line break in an `mcp.jsonc` header value is a source error, and a variable reference with a line break is literal in Claude Code, OpenCode and Antigravity (not adopted by `init`); variable names in the source must not end in a line break; in Codex a server, header or variable name ending in a line break is reported as `Unsupported` instead of breaking the whole Codex plan (#3).
- OpenCode: a v1 file whose `mcp` entries only switch servers on or off (`{"enabled": false}`) is recognised as the v1 layout (also when the v1 server is named `servers`), so a same-name source server is a `Conflict` instead of a second entry (#3).
- Codex: a `startup_timeout_sec` above a 64-bit TOML integer is reported as `Unsupported` and not written, since reading it back would drop it (#3).
- Claude Code: an owned server whose entry holds any literal header (also a short value under a custom header name) is not removed or replaced through `claude mcp`, since its old JSON would reach the inverse command line and the journal; it is a `Conflict` whose reason masks a key name that looks like a secret (#3).
- Codex: a boolean `startup_timeout_sec` in the user's file is no longer taken as equal to `1` second (#3).
- OpenCode: removing the last v1 server no longer fails when its name matches a top-level key such as `mcp` or `$schema` (#3).
- Secret detection: the fallback of a reference (`${NAME:-fallback}`, `{env:NAME:...}`) is masked as a whole wherever it appears and is treated as a possible secret (so it is refused in `mcp.jsonc` `env` and refused on owned Claude Code entries); these forms no longer count as plain variable references, so a literal fallback is masked in plans, in `Bearer`, `name=value` and URL credentials and after a secret flag (`--token`), and refused on owned Claude Code entries; `init` masks a field name that looks like a credential in its warnings and `// Note:` comments (#3).
- OpenCode: the post-edit check looks in the object it edited, so removing the last v1 server cannot hide a duplicate key that survives the edit (#3).
- `init` (Claude Code, OpenCode): every `env`/`environment` entry the reader does not import (a fallback such as `${NAME:-x}`, a reference to a variable of another name, or a key under OpenCode's legacy `env` alias) gets a note, so the server is not adopted and a later `sync` cannot silently drop that entry (#3).
- Masking: only a plain `%NAME%` counts as a Windows-style reference (a percent-encoded value is masked). A credential after `Bearer`, in URL userinfo, in `name=value` or in an `Authorization`-style header is kept only when the WHOLE value is a plain reference (a compound value such as `${PREFIX};suffix` is masked), and a nested fallback is masked up to its matching closing brace (an escaped brace never closes it; printed text and plans mask fallbacks before splitting into lines) (#3).
- Codex `init`: an `env` literal that overrides a name in `env_vars` gets a note, so the server is not adopted and `sync` cannot drop the override (#3).
- Claude Code: a key name that is itself a credential (for example a token-shaped header name) makes an owned entry a `Conflict`, with the name masked (#3).
- `init` (all four tools): a non-string `env` value that the reader drops gets a note too, so the server is not adopted (#3).
- OpenCode and Antigravity: a number in a boolean switch (`"disabled": 1`) is no longer taken as equal to `true`, so it is corrected instead of being reported in sync or rewritten unchanged on every run (#3).
- OpenCode: an empty `"environment"` or `"env"` object counts as absent (no change planned right after `init`), and a non-object `env`/`environment` gets an import note (#3).
- Secrets in names: an `env` name that is itself a credential is treated as secret (dropped on import, refused in `mcp.jsonc`), and every `ImportNote` masks its field name when it is created (#3).
- All adapters: a `headers` (Codex `http_headers`) value that is not an object counts as literal: `init` notes it and leaves the server unowned, and `sync` reports a `Conflict` for an unowned entry instead of removing it (#3).
- `env` that is not an object: `init` notes it in all four tools (so the server is not adopted), and an owned Claude Code entry with a non-object `env` or `headers` is a `Conflict`; in OpenCode a `null` `headers`/`environment`/`env` counts as absent (#3).
- A bad `env`/`headers` value (a list, string, number or `false`) is never taken for an empty one when comparing (Claude Code, Codex, Antigravity), so it is a `Conflict` or a correction instead of "in sync"; an owned Claude Code entry with a non-string `env` value is a `Conflict` (#3).
- A header name that is itself a credential is refused in `mcp.jsonc`, dropped and noted on import (Claude Code, OpenCode, Codex `env_http_headers`), and literal for the unowned-entry check; error messages mask such names (#3).
- A VARIABLE name that is itself a credential (in `env_vars`, a same-name `env` reference, a header reference, Codex `bearer_token_env_var` or `env_http_headers`) is refused in `mcp.jsonc` and never imported: `init` notes it, and the unowned-entry check treats such a header as literal (#3).
- A header SCHEME that is itself a credential (`<token> ${NAME}`) is refused in `mcp.jsonc` and literal on import (Claude Code, OpenCode, Antigravity); Antigravity also treats credential-shaped header or variable names as literal, and corrects a non-boolean `disabled` (#3).
- A plain reference whose variable name is itself a credential (`${<token>}`) is not a reference: it is masked, refused on owned Claude Code entries and in `mcp.jsonc`; `server_secret_problems` applies the same name checks to every header shape (#3).
- Codex: an invalid `env_vars` entry, a non-table `env_http_headers`, a header variable that is not a valid name, or a non-string `bearer_token_env_var` is never imported and gets a note; a non-boolean `enabled` and non-list `args`/`env_vars` are compared as they are (Claude Code and Antigravity also keep bad `args`) (#3).
- Masking: a reference whose variable name is itself a credential (`${<token>}`, `{env:<token>}`, `$<token>`, `%<token>%`) has that name masked anywhere in a text, so it is refused in the source and never shown in a plan; an import note never carries a rejected value (Codex names a rejected `env_vars` entry by position) (#3).
- Codex: an `env_vars` item the reader skips (a `source = "remote"` entry, a malformed item) gets a note, and an owned server that holds one is a `Conflict` on change, so the item is never lost; Antigravity: an edit that a key written twice would defeat fails and leaves the file unchanged, as in OpenCode (#3).
- Masking: a credential-shaped name padded with spaces, a bare `$<token>` right after a word, and a fallback whose quoted part holds a brace are all masked; an owned Codex server whose `env_vars` hold an item all-agents cannot keep (a remote variable) is a `Conflict` on change instead of losing it; a position-named import note (`env_vars[2]`) asks to check that entry (#3).
- Names that are credentials (padded too) are shown as `***` everywhere: Conflict reasons, error messages, import notes and JSON keys in a rendered plan (`mask_name`) (#3).
- A server NAME that is itself a credential is refused in `mcp.jsonc` (without showing it) and never imported by `init`; Codex treats an `env_vars` name that is not valid as an item it cannot keep (a `Conflict` on change); a quoted part of a fallback never closes it (a `\"` inside double quotes does not end the quote), and may span lines only when the fallback then closes, so a stray apostrophe never hides the lines after it (#3).
- Codex: an unowned server whose `env_vars` hold a name that was not imported is a `Conflict`; a rendered plan masks `Authorization`/`Cookie` values and numbers under secret names in JSON arguments; `McpServer` errors mask credential-shaped names (#3).
- Claude Code: a number or a structure under a credential key (`access_token`, `cookie`, ...) makes an owned entry a `Conflict`; a rendered plan masks such values and a server name that is itself a credential; Codex: an unowned server with a local `env_vars` table whose name was not imported is a `Conflict` (#3).
- Plans: a JSON argument is masked and checked field by field (a URL inside it no longer causes a false secret refusal, and a broken pattern match can no longer expose its fields); a number after a secret flag (`--api-key 12345`) is masked and refused on owned Claude Code entries; each plan entry is masked on its own, so a stray quote never hides the entries after it (#3).
- A JSON document passed as one argument (`{"api_key": "..."}`) is masked field by field everywhere (`mask_args`, source checks, Claude Code's owned-entry check, plans); when one Claude Code command of a plan holds a secret, every command of that tool and kind is held back (a replacement is a remove plus an add), and a new Claude Code entry with a secret-looking value is a `Conflict` before anything is removed (#3).
- Masking JSON: `<scheme> <reference>` counts as a reference only inside `headers` (one space, a valid non-credential scheme, no line break), so `literal ${VAR}` under a secret key is masked and refused; anything right after a secret flag in any list (a string, number or structure) is masked; an empty value under a secret key is not taken for a secret (#3).
- Masking: a JSON argument with a key written twice is masked whole and refused (`loads_strict`); a value starting with `-` right after a secret flag (`--token -123456`) is masked unless it looks like a flag; an `env` value that is a JSON document holding a secret looks secret, so all four adapters drop and note it on import (#3).
- A parsed JSON document is judged only field by field (text patterns no longer run across its delimiters, so a URL next to an `@` is not a false secret); `authorization` and `cookie` names hold secrets for every check (env values included); a held-back Claude Code replacement is one conflict keyed by its server, with the direct reason kept over the "not run" one (#3).
- Masking: `--cookie`/`--authorization` flags and `cookie=` assignments hold secrets; only exactly `-x` or `--name` after a secret flag counts as a flag; a JSON argument the parser cannot inspect (a huge number, deep nesting) is masked whole; `status --json` and an engine refusal mask credential-shaped item names, and held-back commands are de-duplicated by the real item, not its masked name (#3).
- Masking: a value inside a string opened before its name (`"token=${T}" "next"`, `{"a": "Bearer ${T}", ...}`) ends at that string's closing quote, and the text after it is searched again, so a clean JSON line or shell line is never swallowed; a plain `{env:NAME}`/`{{NAME}}` reference after `name=` or a secret `--flag=` is kept; the refusal messages of Codex, OpenCode and Claude Code show variable, header and scheme names through `mask_name` (#3).
- Masking: the flag name of `--flag=<json>` is masked too when it is a misfiled token; a quoted part of a bare value that has its own closing quote is masked whole, also when it starts with a space (`abc" tail"`); a JSON `pwd` field is a secret field (the shell's `PWD` under `env` is not) (#3).
- Masking: JSON attached to a flag (`--config={...}`) is judged field by field like a JSON argument, and masked whole after a secret flag; a quoted part inside a bare value (`abc"my secret"`) is masked to its closing quote; `X-Auth-Key:`/`Auth-Key:` are credential headers; masking an unclosed value that ends in a backslash keeps a CRLF line end (#3).
- OpenCode reads a `timeout.startup` written as a whole-number float (`45000.0`) as its seconds, like Codex, and keeps it as written (it is the same integer to OpenCode's schema, so an adopted server shows no drift); the post-edit checks of OpenCode, Codex and Antigravity (and the Claude Code variable-name message) show a server or variable name through `mask_name` (#3).
- Masking: a closing quote ends a value only when the value really ends there (a space, punctuation or the end of the line); text glued right after it (`token="${T}"tail`, `-H 'X-Api-Key: 'tail`) keeps the whole value masked, and a quote inside a bare value (`token=abc"def`) no longer ends it (#3).
- `status --json` masks every string before serialising, so masking can never cut into the JSON (a name such as `demo-cookie:` produced invalid JSON); `auth.key`/`auth_key`/`auth-key` are secret names for flags, JSON keys and env keys; an unclosed quoted value that ends in a backslash is still masked (#3).
- Masking: a credential header written as text is masked whole to the end of its line (or to the quote that encloses the argument, as in `-H 'Cookie: ...'`) unless the whole value is a reference, so text after a quoted part never stays visible; a quoted value after `Bearer`/`Basic` or a secret-sounding `name=` is judged inside its quotes; dotted secret flags (`--api.key`, `--auth.token`) are secret flags (#3).
- Masking: a quoted credential header value (`Authorization: "<literal>"`) is masked inside its quotes, so it is refused in the source and never reaches a command or the journal; an import note marks a hidden (credential-shaped) server from its raw name, so a server really named `***` keeps its notes and is not adopted (#3).
- Masking: a credential header written as text (`Authorization:`, `Proxy-Authorization:`, `Cookie:`, API-key headers) is masked whole, to the end of the line or quote, unless it is a plain reference alone or after a scheme (`Token ${NAME}`), so `Authorization: Token <literal>` and `Cookie: sid=<literal>` are masked and refused; a `--name_with_underscore` flag after a secret flag stays a flag, so the value after it is masked; `status` shows a pending item's name through `mask_name`, one item per original name; a Claude Code entry nested too deep to inspect is refused instead of crashing the plan; Claude Code command descriptions never carry a credential-shaped server name (#3).
- An import note never carries a credential-shaped server name raw (masked like the field name); `status --json` keeps one conflict item per conflict, so two names that mask alike stay two items; a held-back command's direct secret reason replaces the conflict of its own server only, not an earlier one with the same masked name (#3).
- Claude Code: a clean JSON value in `env` or `args` is no longer refused by text patterns that ran across its delimiters (the owned-entry check judges JSON field by field, like every other check) (#3).
- JSONC editor: removing a member keeps a `/* ... */` comment that starts on the previous member's line and spans lines whole (#3).

## [0.1.0] - 2026-11-10

### Added
- Core CLI commands: `init`, `sync`, `status`, and `undo`.
- Tool adapters for Claude Code, Codex, OpenCode, and Antigravity.
- Unified reversible engine with atomic writes, pre-write backups, and unified journal.
- Real tool verification reports in `docs/verification/` for Windows, Linux (WSL), and macOS CI.
- Automated documentation integrity tests (`test_docs_readme.py`, `test_docs_support_table.py`, `test_docs_security.py`, `test_docs_github_metadata.py`).
- Security policy and vulnerability disclosure process in `SECURITY.md`.
- Automated GitHub Actions release workflow with PyPI Trusted Publishing (OIDC).
